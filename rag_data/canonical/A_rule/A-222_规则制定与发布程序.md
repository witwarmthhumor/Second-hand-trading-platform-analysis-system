# 规则制定与发布程序

> 制度编号：RL-A-222　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

规则的公信力来自程序。本章规定规则从提案到发布的完整程序，依据《平台规则体系总览》（RL-A-221）制定。

## 第二章 程序流程表

| 环节 | 内容 | 输出 |
| 提案 | 规则委员会、治理团队或用户反馈发起 | 提案说明 |
| 评估 | 合规审查、影响面评估 | 评估报告 |
| 征求意见 | 涉及重大利益的规则公示征求意见 | 意见汇总 |
| 审议 | 规则委员会表决 | 审议结论 |
| 发布 | 规则中心公示，标注生效日期 | 正式文本 |

## 第三章 正文条款

第1条 涉及用户重大利益调整的规则（如费率、保证金），发布与生效之间保留过渡期，过渡期长度随公告载明。

第2条 征求意见阶段收到的用户意见，处理结论在发布说明中概括回应，采纳与否都有交代。

第3条 紧急治理需要（如新型诈骗爆发）可走快速发布程序，事后补足评估与说明。

补充说明：征求意见环节是普通用户参与规则制定的真实入口。历史上多项规则调整都来自用户反馈——比如退货流程的影像指引、验货报告的可读性重构，最初的提案都来自用户反馈入口。规则不是平台单方面的意志，而是在用户参与的程序中长出来的。看到不合理的规则，提交你的反馈，这比在社区里抱怨有用一百倍。

补充说明：规则制定程序里有一个容易被低估的环节是影响面评估。一个看似简单的条款调整，可能影响数十万在途订单与数百万存量商品。评估报告会测算调整对买卖双方、对不同品类、对不同经营规模的差异化影响，确保调整的收益大于代价。下次看到某条规则的过渡期特别长，那不是拖延，而是评估结论的具体体现。

补充：征求意见的公示期通常为数周，重大调整会更长，公示期的长短在征求意见公告的头部载明。

补充：制定程序中还有一个征求意见的细则性要求：反馈意见的处理结论应当在发布说明中概括回应，这意味着提交过意见的用户可以看到自己的意见是否被采纳以及理由。这种回应机制保证了征求意见不是形式主义，也是用户持续参与规则共建的信心来源。意见被采纳的用户，其建议会在发布说明中标注来源。

## 第四章 违规处理与责任

绕过程序发布规则文本、伪造规则公告的，按妨害治理处理；内部责任人的程序违规由规则委员会追责。
