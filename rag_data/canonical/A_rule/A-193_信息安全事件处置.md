# 信息安全事件处置

> 制度编号：RL-A-193　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

本章规定信息安全事件的分级、处置流程与通报机制，依据《个人信息使用规则》（RL-A-183）制定，覆盖数据泄露、越权访问、系统入侵等情形。

## 第二章 正文条款

第1条 事件分级：按影响范围与数据敏感度分为重大、较大、一般三级，分级决定响应层级与通报范围。

第2条 处置流程：发现即隔离止损、评估影响范围、修复漏洞、按法定要求向监管通报、对受影响用户逐一告知。

第3条 用户告知内容包含：事件类型、可能的影响、已采取的措施、用户可自行采取的防护建议。

第4条 事件复盘形成整改报告，整改措施纳入后续的风控与审计安排。

## 第三章 处置时效与责任表

| 环节 | 要求 |
| 止损隔离 | 发现后立即 |
| 影响评估 | 即时启动 |
| 用户告知 | 按法定要求 |
| 整改复盘 | 处置完成后限期 |

补充说明：信息安全事件的分级响应还有一个用户侧的配合要求：收到事件告知后，建议用户按告知中的防护建议操作，比如修改密码、检查账户活动记录。事件的平台侧处置与用户侧的自助防护是互补的，平台拦截攻击者的同时，用户改掉可能泄露的密码，能让事件的实际影响降到最低。防护建议都是具体可执行的，不要因为看起来简单就跳过。

补充说明：安全事件的分级通报还有一个面向行业的维度：涉及行业共性的攻击手法，平台会在脱敏后与同业共享防护经验，这种行业协同能让整个生态的防护水位一起上升。单点防护的时代已经过去，攻击者的手法是跨平台流动的，防护也必须协同。用户在这个体系中的角色是哨兵，每一次异常举报都在为行业防线提供情报。

补充：事件的用户告知支持订阅，受影响用户可选择邮件或站内信接收后续进展，直到事件处置闭环。

## 第四章 违规处理与责任

隐瞒不报、拖延处置的，责任人顶格追责；构成违法的移交执法部门（来源：penalty 节点）。
