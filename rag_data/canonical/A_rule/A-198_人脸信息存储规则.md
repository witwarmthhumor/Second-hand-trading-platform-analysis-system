# 人脸信息存储规则

> 制度编号：RL-A-198　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

人脸信息属于敏感个人信息中的生物识别信息，保护强度最高。本章规定人脸信息的采集、存储与删除口径，依据《个人信息使用规则》（RL-A-183）与《实名认证信息保护》（RL-A-197）制定。

## 第二章 正文条款

第1条 采集场景唯一：实名认证与人脸验证的核验环节，其他任何场景不采集人脸。

第2条 存储形态：核验完成后仅保留验证结果（通过/不通过），人脸原图与特征模板按技术允许的最短周期删除。

第3条 用户可在「我的-设置-隐私」查看人脸验证的授权状态并申请删除残留特征数据。

第4条 人脸数据不用于行为分析、不用于营销、不对外共享，任何其他用途须单独取得书面同意。

## 第三章 保护措施明细表

| 措施 | 说明 |
| 场景限定 | 仅实名核验采集 |
| 最短留存 | 验证后限期删除 |
| 单独同意 | 扩展用途须书面同意 |
| 状态可查 | 授权状态随时可见 |

补充说明：人脸信息的删除申请生效后有一个需要注意的细节：删除后再次使用人脸验证功能时需要重新采集。重新采集会重新走一遍授权流程，这是敏感信息保护的正常代价。如果用户的人脸验证使用频率很高，可以考虑改用指纹或其他验证方式替代，减少人脸数据的重复采集。数据最小化原则的落实，需要用户与平台的双向配合。

补充说明：人脸信息还有一个用户关心的追问：验证时闭眼、侧脸会不会影响验证结果导致反复采集。核验系统对采集质量有引导提示，正常配合完成即可，多次失败的场景系统会引导改用其他验证方式，而不是反复采集人脸。这个设计避免了失败重试带来的人脸数据过度采集，也是最小必要原则的体现。

补充：人脸验证状态的查看不需要人脸再验证，状态页本身不涉及敏感操作，打开即看。

## 第四章 违规处理与责任

留存、倒卖人脸数据的，永久封禁并移交执法部门；内部越权的顶格追责（来源：penalty 节点）。
