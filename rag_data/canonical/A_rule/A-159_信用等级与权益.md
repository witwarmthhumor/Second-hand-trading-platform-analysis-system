# 信用等级与权益

> 制度编号：RL-A-159　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

本章规定信用分对应的等级划分与各等级权益，依据《信用分体系总则》（RL-A-156）制定。

## 第二章 等级与权益速查表

| 等级 | 区间口径 | 核心权益 |
| 极高 | 接近上限区间 | 专属活动优先、客服快线 |
| 高 | 高于初始分区间 | 活动报名优先、权益礼包 |
| 中高 | 初始分附近区间 | 标准权益 |
| 中 | 中等偏下区间 | 标准权益，部分活动受限 |
| 低 | 中等偏下至警戒区间 | 大额交易二次确认 |
| 极低 | 警戒线附近至下限 | 下单功能限制，逐单核验 |

## 第三章 正文条款

第1条 等级按信用分实时映射，等级权益的生效与失效随分值变动即时切换。

第2条 警戒线附近及以下的用户，下单限制以核验为主，目的是降低欺诈场景的受害人范围，不是剥夺交易资格。

第3条 等级权益的详细清单在权益中心公示，调整随版本更新公告。

补充说明：等级区间采用定性口径而不用具体数字划线，是刻意的设计：分值的绝对位置不如相对位置有意义，接近上限与接近下限的权益差异才是用户真正需要感知的。系统按全量分值的分布动态校准区间边界，避免通货膨胀或通缩导致等级失真，这也意味着等级反映的是你在全体用户中的相对位置。

补充说明：权益的实时映射偶尔会出现延迟感知，比如刚回升分数但权益还没刷新，这通常是页面缓存所致，重新登录即可刷新。权益的收回是即时生效的，给予的方式是宽容的，收回是严格的，这个不对称是风险管理的标准做法。

补充说明：等级权益的另一个设计细节是权益的申请成本：高等级权益大多免申请自动生效，只有极少数大额权益需要手动开启。这是为了避免权益的沉默失效——系统把能自动给的都自动给了，用户只需要知道自己的等级，权益就跟着走。等级页的权益对照表会明确标注每一项是自动还是申请制。

## 第四章 违规处理与责任

利用等级权益从事活动套利的，收回权益并按虚假交易口径处理（RL-A-131）。
