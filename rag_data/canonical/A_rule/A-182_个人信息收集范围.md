# 个人信息收集范围

> 制度编号：RL-A-182　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

本章规定平台收集个人信息的范围与边界，依据《隐私政策摘要》（RL-A-181）制定。收集的原则是最小必要：功能必需的才收集，与功能无关的一律不收。

## 第二章 正文条款

第1条 注册与账户类信息：手机号、昵称、头像、登录凭据。收集目的是建立与保护账户。

第2条 实名与支付类信息：身份证明信息、收款账户信息。收集目的是满足交易与资金合规要求，拒绝提供则对应功能无法使用。

第3条 交易履约类信息：订单信息、收货人信息、物流信息。收集目的是完成交易闭环与售后举证。

第4条 设备与日志类信息：设备型号、操作系统、操作日志。收集目的是安全风控与故障排查。

第5条 可选授权类信息：位置信息、相册访问、通讯录（仅用于邀请好友的授权场景）。拒绝授权不影响核心交易功能。

## 第三章 收集边界清单

| 边界 | 说明 |
| 不收集 | 与交易无关的社交关系链分析数据 |
| 不收集 | 非必要的人脸样本留存（仅验证不留存原图） |
| 不收集 | 精准定位轨迹（仅模糊位置用于质检仓展示） |
| 可关闭 | 个性化推荐所需的浏览行为分析 |

补充说明：最小必要原则的落地依靠的是功能与数据的对应审查：每一个新功能上线前，都要回答它需要哪些数据、为什么需要、不用这些数据行不行。回答不了的数据需求就不上。这套机制对用户的直接意义是：你看到的每一个功能，背后都有一次数据必要性的审查。发现某个功能要求了你认为不该给的数据，这就是投诉入口存在的意义。

扩展说明：从用户视角理解收集范围还有一个自查入口——隐私中心的收集清单页会实时展示当前账户实际收集了哪些类别的信息，这份清单与规则的差异会以醒目标识提示。用户不需要去猜平台收了什么，页面上看到的就是全部。发现清单之外的数据诉求，隐私投诉通道会核查。透明本身也是一种约束机制，把规则从纸面搬到了产品里。

## 第四章 违规处理与责任

超出本章范围收集信息的，按《信息安全事件处置》（RL-A-193）追责，并适用累计扣分阶梯（来源：penalty 节点）。
