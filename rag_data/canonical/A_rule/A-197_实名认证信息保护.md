# 实名认证信息保护

> 制度编号：RL-A-197　版本：v3.2　生效日期：2026-06-01　适用对象：全体

## 第一章 总则

实名认证信息是敏感度最高的个人信息。本章规定其保护口径，依据《个人信息使用规则》（RL-A-183）制定，保护强度高于一般个人信息。

## 第二章 正文条款

第1条 存储保护：实名信息加密存储，展示时脱敏处理（身份证号隐藏中间段、姓名部分打码）。

第2条 使用限定：仅用于身份核验、资金安全与法定义务场景，核验完成后不留存证件影像原图。

第3条 查看权限：平台内部按最小必要授权，越权查看按《信息安全事件处置》（RL-A-193）顶格追责。

第4条 用户可随时在个人信息归档中查看实名信息的存储状态（RL-A-188）。

## 第三章 保护措施对照表

| 措施 | 说明 |
| 加密存储 | 强加密算法存储 |
| 脱敏展示 | 默认打码显示 |
| 最小授权 | 按角色分配查看权限 |
| 原图不留存 | 核验完成后删除 |

补充说明：实名信息的脱敏展示有一个统一规则：在任何界面，身份证号只展示前几位与后几位，姓名只展示姓氏与末位。脱敏展示覆盖所有面向用户的界面，包括客服工位的展示（客服看到的是脱敏后的信息）。这意味着即使是平台内部，能完整看到实名信息的也仅限于少数经过授权的核验岗位，普通客服处理业务不需要也不应该看到完整证件号码。

补充说明：实名信息的还有一个高频问题是：为什么有的功能明明是免费的也要实名。原因是合规义务，比如资金相关的功能涉及反洗钱要求，与金额无关与性质有关。平台不能为了体验降低合规标准，但会承诺实名信息的用途与保护与金额无关。理解了这一点，免费功能要实名就不会显得突兀。

补充：实名信息的使用场景在个人信息归档中有专门章节，列明每一类场景的使用依据与范围。

## 第四章 违规处理与责任

泄露实名信息的，顶格追责并承担相应法律责任；买卖实名信息的移交执法部门（来源：penalty 节点）。
