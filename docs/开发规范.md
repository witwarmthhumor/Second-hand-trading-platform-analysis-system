# 开发规范

> 古玩 · 近代钱币 竞品分析系统 — 编码标准
> 本文回答「代码怎么写」，不重复「做什么」（见产品文档）和「怎么做」（见技术方案）。
> 定位：薄、可执行、可校验。`AGENTS.md` 管「必须做什么」，本文管「标准长什么样」。

## 1. 命名规范

| 场景 | 约定 | 示例 |
|------|------|------|
| Python 变量/函数/模块 | `snake_case` | `fetch_competitor()` / `crawler_base.py` |
| Python 类 | `PascalCase` | `LLMProvider` |
| Python 常量 | `UPPER_SNAKE_CASE` | `DEFAULT_TIMEOUT` |
| 数据库表名/字段名 | `snake_case` | `competitors` / `ext_fields` |
| Vue 组件文件 | `PascalCase.vue` | `CompetitorForm.vue` |
| 前端变量/函数 | `camelCase` | `fetchList()` |
| CSS 类名 | `kebab-case` | `.competitor-card` |

**禁用**：拼音命名、无意义缩写（`d`、`tmp2`、`x1`）。缩写仅限约定俗成（`id`、`url`、`api`、`http`）。

目录结构遵循技术方案第七节，此处不重复罗列；新增模块须先在该节登记。

## 2. 代码风格与格式化

| 语言 | 工具 | 配置落点 |
|------|------|----------|
| Python | **ruff**（统一 lint + format） | `backend/pyproject.toml` |
| 前端 | **ESLint + Prettier** | `frontend/.eslintrc.cjs` / `frontend/.prettierrc.json` |

**固定配置**（写入上述落点，不靠命令行临时传参）：

```toml
# pyproject.toml 关键项
[tool.ruff]
line-length = 88
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]   # 错误/格式/import 排序/升级建议/常见 bug
```

- 行宽：Python 88，前端 100。
- 引号：Python 双引号，前端单引号。
- 提交前执行：`ruff check . && ruff format .`；前端 `npm run lint && npm run format`。
- **强制**：本地加 `pre-commit` hook（`.pre-commit-config.yaml`），把「跑格式化」从人肉提醒变成自动执行。未装 hook 前，每次提交先手动跑一遍。

## 3. 分支与提交规范

- 分支：`main`（稳定主线）+ `feat/xxx`、`fix/xxx`，完成后合入 `main`。
- 提交信息：Conventional Commits，格式 `type(scope): subject`。
  - type：`feat` / `fix` / `docs` / `chore` / `refactor` / `test`
  - 示例：`feat(stage1): 竞品 CRUD 接口`
- 每条提交原子性：只做一件事。文档改动与代码改动分开提交。

## 4. 测试规范

**覆盖目标（可量化）**：

| 目标 | 最低要求 |
|------|----------|
| 状态机迁移 | 每条迁移路径至少 1 个用例（`draft→待校对`、`待校对→已入库`、`待校对→draft` 降级） |
| CRUD 接口 | 每个接口 1 正常 + 1 异常（参数缺失/非法） |
| 爬虫解析 | 用 fixture 固定 2~3 个真实样本 HTML，覆盖字段提取健壮性 |
| LLM 提炼 | 全程 mock，验证结构化输出 schema 校验通过/失败两条路径 |
| 对比查询 | 空列表、单条、多条三个边界 |

- 爬虫 / LLM **不依赖真实网络与模型**，一律 mock。
- 交付前所有测试通过（呼应 `AGENTS.md` 第二条）。
- 运行：`pytest`。核心链路（采集→提炼→校对→入库）必须有一条端到端用例。

## 5. API 规范

**统一响应结构**：HTTP 状态码正常路径返回 `200`，业务结果由 `code` 区分。

```json
{ "code": 0, "message": "ok", "data": { } }
```

**最小错误码表**：

| code | 含义 | 对应 HTTP |
|------|------|-----------|
| 0 | 成功 | 200 |
| 1 | 参数错误 | 400 |
| 2 | 未授权 | 401 |
| 3 | 资源不存在 | 404 |
| 4 | 业务冲突（如重复提交） | 409 |
| 5 | 服务内部错误 | 500 |

- 路径命名：`/api/资源名`（一律复数）。
- 嵌套子资源：`/api/competitors/{id}/reports`（父资源单数 id + 子资源复数）。
- HTTP 方法语义：GET 查 / POST 增 / PUT 改 / DELETE 删。
- 已有路由（`/api/crawl`、`/api/review`、`/api/compare` 等）按技术方案第六节，新增接口遵循本表。

## 6. 类型标注与注释

- **所有新增函数（含私有）必须类型标注**，公共函数加 docstring（一句话 + 参数/返回值）。
- **强制注释**（简历讲解重点）：
  - `crawler/` 爬虫解析逻辑
  - `ai/` 提炼与 Provider 实现
  - 状态机流转等复杂业务逻辑——注释说明「为什么」，不是复述代码。
- Pydantic schema 字段加 `description`（供 LLM JSON Schema 约束与前端提示复用）。

## 7. 配置与日志

- 敏感信息（数据库连接、LLM 密钥）走 `.env`，**不进 git**；`.env.example` 同步字段模板（技术方案第七节）。
- 日志：统一 `logging`，关键节点必须记录——采集发起/成功/失败、提炼调用、状态机迁移、入库结果。
- Python 版本：`requires-python = ">=3.11"`，锁定在 `pyproject.toml`。
