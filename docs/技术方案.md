# 技术方案

> 古玩 · 近代钱币 竞品分析系统 — 技术实现文档
> 本文是产品设计文档（`docs/产品设计文档.md`）的技术配套，聚焦「怎么做」，不重复「做什么」。

## 一、技术选型总览

| 层 | 选型 |
|----|------|
| 后端框架 | FastAPI |
| ORM | SQLAlchemy 2.x（异步） |
| 数据校验 | Pydantic v2 |
| 数据库 | PostgreSQL（Docker 容器运行） |
| 数据库迁移 | Alembic |
| 爬虫 | httpx + BeautifulSoup4 |
| AI 接入 | 可插拔 LLM Provider 抽象层（先接当前对话模型） |
| 前端框架 | Vue 3 + Vite |
| UI 组件库 | Element Plus |
| 图表 | ECharts |
| HTTP 客户端 | Axios |
| 任务调度 | APScheduler（阶段 4 引入） |
| 消息队列 | 不引入（库内状态机替代） |
| 测试 | pytest |
| 版本管理 | Git（main + feat，Conventional Commits） |

## 二、选型理由

每一项选型回溯到产品文档的具体需求：

| 产品需求 | 选型决策 |
|----------|----------|
| 半自动采集 + AI 提炼 + 人工校对 | 异步爬虫（httpx）+ 可插拔 LLM + 库内状态机（draft / 待校对 / 已入库） |
| 多竞品对比 + 雷达图 | ECharts + 后端对比查询 API |
| 通用维度 + 扩展字段（不同平台类型） | PostgreSQL JSONB 存扩展字段，枚举可扩展 |
| 可维护性：新增平台类型无需重构 | JSONB 扩展字段 + 平台类型枚举表 |
| 展示「AI 工程落地能力」 | Provider 抽象层 + Pydantic 结构化输出（核心亮点） |
| 安全性：密钥不入库 | `.env` 进 `.gitignore`，提供 `.env.example` |
| 本地跑通、暂不部署 | Docker 提供 PostgreSQL，零配置 |

**关键取舍说明**：
- **不引入 Celery/消息队列**：单用户本地项目无并发压力，「待校对」用数据库状态字段表达即可；引入队列属过度设计。
- **爬虫用 BeautifulSoup4 而非 selectolax**：纯 Python 零编译，Windows 本地开发更省心，抓取量小性能非瓶颈。
- **前端选 Vue 3 而非 React**：后台 CRUD 类场景配 Element Plus 开发效率最高。

## 三、系统架构

```
┌─────────────────────────────────────────────┐
│                 前端 (Vue 3)                  │
│   列表页 / 录入表单 / 对比页（Element Plus +  │
│   ECharts 雷达图）                            │
└──────────────────────┬──────────────────────┘
                       │ Axios (REST / JSON)
┌──────────────────────▼──────────────────────┐
│              后端 (FastAPI)                   │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ api 路由  │ │ services │ │  schemas     │ │
│  │ (CRUD/   │ │ (业务逻辑) │ │ (Pydantic)  │ │
│  │  对比)   │ └──────────┘ └──────────────┘ │
│  └──────────┘         │                      │
│       ┌───────────────┼───────────────┐      │
│       ▼               ▼               ▼      │
│  ┌──────────┐  ┌───────────┐  ┌──────────┐  │
│  │ crawler  │  │ ai (LLM   │  │ models   │  │
│  │ httpx+BS4│  │ Provider) │  │ SQLAlchemy│  │
│  └──────────┘  └───────────┘  └──────────┘  │
└──────────────────────┬──────────────────────┘
                       │ SQLAlchemy (asyncpg)
┌──────────────────────▼──────────────────────┐
│           PostgreSQL (Docker 容器)           │
│  竞品表 (含 JSONB 扩展字段 + 状态字段)          │
└─────────────────────────────────────────────┘
```

**分层职责**：
- `api`：路由与请求响应处理
- `services`：业务逻辑（录入、对比、采集编排）
- `models`：ORM 模型
- `schemas`：Pydantic 校验模型（含 LLM 输出 schema）
- `crawler`：网页抓取
- `ai`：LLM Provider 抽象与提炼逻辑

## 四、数据模型设计

### 竞品实体（核心表 `competitors`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | 主键 | 自增 |
| name | String | 名称（必填） |
| type | String/枚举 | 平台类型：鉴定/交易/行情/社区（可扩展） |
| positioning | String | 一句话定位 |
| website | String | 官网 |
| status | String | 上线状态：已上线/内测/已下线 |
| features | Text | 核心功能 |
| target_users | String | 目标用户 |
| business_model | String | 业务模式 |
| pricing | String | 定价方式 |
| strengths | Text | 优势 |
| weaknesses | Text | 不足 |
| tags | JSONB/ARRAY | 标签 |
| remark | Text | 备注 |
| ext_fields | JSONB | **扩展字段**（不同平台类型的专属字段，可扩展无需迁移） |
| status_flow | String | 数据状态机：draft / 待校对 / 已入库 |
| created_at / updated_at | Timestamp | 时间戳 |

### 状态机（数据流转）

```
draft ──抓取/提炼──▶ 待校对 ──人工确认──▶ 已入库
  ▲                    │
  └─────── 降级/驳回 ──┘
```

- 手动录入：直接 `已入库`
- 半自动采集：抓取 → AI 提炼 → `待校对` → 人工确认 → `已入库`

## 五、AI 提炼链路设计

### Provider 抽象层

```python
class LLMProvider(ABC):
    async def extract(self, content: str) -> CompetitorExtraction:
        """从网页内容提炼结构化竞品信息"""
```

- 默认实现：对接当前对话模型
- 预留：DeepSeek / OpenAI / 通义 等实现，通过配置切换

### 结构化输出

- 定义 `CompetitorExtraction` Pydantic schema，约束 LLM 输出字段。
- 用 JSON Schema 约束，确保 LLM 输出可校验、可入库。
- 提炼失败时降级为手动录入，不影响主流程。

### 校对流程

- 提炼结果状态置为 `待校对`，进入待校对列表。
- 人工确认/修正后置为 `已入库`。

## 六、前后端 API 概览（阶段 1~3）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/competitors | 列表（支持搜索/类型筛选） |
| POST | /api/competitors | 手动录入 |
| GET | /api/competitors/{id} | 详情 |
| PUT | /api/competitors/{id} | 编辑 |
| DELETE | /api/competitors/{id} | 删除 |
| POST | /api/crawl | 提交网址，抓取并提炼（进入待校对） |
| GET | /api/review | 待校对列表 |
| POST | /api/review/{id}/confirm | 确认入库 |
| GET | /api/compare?ids=1,2,3 | 多竞品对比数据 |
